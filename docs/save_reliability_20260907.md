# 保存処理の限定修正（2026-09-07）

利用者の「大きく変更して安定性を損なわないことを優先する」という方針に従い、保存方式やシート構成を維持して、監査で再現した3件だけを修正する。

## 変更対象

- **F3・端末履歴の保存失敗**：書込み失敗を保存済み扱いにせず、失敗した完了履歴を再試行できるようにする。重複登録、明示消去した履歴の復活、クラウド得点の二重送信を避ける。
- **F4・累積集計の競合**：同じサーバープロセス内で、同じスプレッドシート・集計シート・名前の読取→更新→確認を直列化する。既存の「累積を引き下げない」計算、通信再試行、保存IDは維持する。他の名前・集計シートの更新は独立に進める。
- **F5・集計シートの列不足**：ランキング取得時に `UserStats` の `user` / `total_points` がそれぞれ1列あるかを検証する。正常な `Scores` が読めればログから表示し、両方とも読めなければ取得失敗として扱う。正当な0点は引き続き表示する。

F3の再試行は、新しい失敗マーカーを保存できた完了セッションが対象。旧版の保存済みフラグしか残っていない結果や、マーカーのない旧結果から、消去したか失敗したかを推測して履歴を作り直さない。

## 今回見送った変更と運用

**F1・古いタブによる進行状況の上書き、F2・古いタブによる端末履歴の上書きは未修正。** 所有権・履歴統合・削除の扱いを伴う保存方式の変更は、別途設計と十分な検証が必要となるため、この限定修正には含めない。

同時に回答しないだけでは回避できない。ホーム・学習記録画面のタブも進行状況を保持し、非表示や終了時に保存する。**学習開始前に同じブラウザのこのアプリを1つのタブ・ウィンドウにする。別ウィンドウや同時に開いたPWAも残さない。** すでに複数タブで進めていた場合は、古いタブを閉じる際の保存自体が競合し得るので、単に閉じれば進行状態を自動的に修復できるわけではない。

F4の排他制御は同一Pythonプロセス内が対象。複数プロセス、別の実行プログラム、Sheetsの手動編集との完全な直列化は保証しない。正本は引き続き `Scores` で、保存IDによる重複排除と集計表が古い場合のログ併用を維持する。

## 検証

修正前のコードで、履歴書込み失敗後の誤った保存済みフラグ、同じ名前の交錯した集計更新による225→200点への巻戻り、不正な集計列とログ読込失敗の組合せによる成功応答を再現した。

対象版：`2026-09-07-save-recovery-1`。

- Python全138件、JavaScript全81件、Chromiumのブラウザー回帰全29件が成功。
- ブラウザーではPC・スマートフォン幅のスクロール、品詞内の難易度折りたたみ、例文テーマ、公開設定、旧URL、多言語、得点の自動保存、保存確認の復元を維持。
- 音声を含むアセット検査が成功。単語2,890件・例文5,000件とWAV 15,768ファイルの対応を確認。
- 別担当がF3〜F5を独立レビューし、通常処理を妨げる具体的な問題は見つからなかった。

Google Sheetsを使う書込み・障害テストはローカル専用のメモリ内シートで実施。これらの結果は本番データ全件の無誤りや、複数タブの安全性を保証するものではない。

教材CSV、生成済みの問題JSON、音声ファイル、得点計算、スクロール用のCSS、アカウントの公開設定仕様は変更対象外。本番Sheetsのテスト書込みや既存点数の一括修復は行わない。
