# 学習記録の追加監査（2026-09-06）

スクロール修正の本番反映後、画面の高さ、問題の切替、アカウント公開設定、端末保存の失敗経路を追加で確認しました。以下の条件を再現し、修正と回帰テストを追加しています。

| 条件 | 確認した問題と修正 |
|---|---|
| 高さの小さいウィンドウ | iframe自身の高さを使っていたため、外側のウィンドウより高くなり、上下のメニューが画面外に出る。Streamlit親画面の利用可能な高さを使い、リサイズにも追随する。 |
| 長い問題を下へスクロールして回答 | 次の問題にも下の位置を引き継ぐ。新しい問題では先頭へ戻し、誤答フィードバック中の再描画では位置を維持する。 |
| 別originのページ内に埋め込み | 親へのスクロールが拒否された後、catchで同じアクセスを繰り返して例外が漏れる。拒否された親には再実行しない。 |
| 別タブで非公開にしてから進捗を更新 | 新しい非公開設定を確認しても古いランキング表示が残る。古い一覧と待機中の読取要求を無効化し、設定確認後に取り直す。設定の読取失敗時は古い一覧を出さない。 |
| 制御文字を含む名前 | 正規化された応答名が要求名と一致せず、入力エラーを受け取れずに通信待ちになる。応答は要求名をそのまま返し、制御文字は正規化前に拒否して別名への保存も防ぐ。 |
| 端末保存の容量不足 | 設定保存のために端末履歴を自動削除し、履歴にしか残っていない保存済みの証拠まで失う場合がある。設定保存では履歴を削除せず、その他の容量回復でも保存済みの証拠を保護する。 |
| 静的PWAの初回オフライン再訪 | 保存済みのHTMLと入口URLが一致しない場合に起動できない。アプリの入口へのナビゲーションだけ、事前保存したHTMLへフォールバックする。 |

ブラウザー回帰では、Cloud相当の入れ子iframeで高さ500・600・420pxへの変更、下部メニューへのポインター到達、長い問題へのホイール操作、正答・誤答後の次問表示を確認します。公開設定、端末容量不足、オフライン処理は実際のアプリ関数を使う回帰テストで再現します。

本番の読み取り確認と、メモリ内の仮シートを使う検証を分けています。本番に仮の得点を追加したり、利用者の公開設定を変更したりはしません。静的PWAの問題はService Workerを使わないStreamlit本番には該当しません。

確定したテスト結果はGitHubのPRチェックを参照してください。Safari・Firefoxや全てのスマートフォン実機を検査したものではなく、あらゆる障害や同時操作に対する無欠陥の保証ではありません。
