# 履歴保存の追加限定修正（2026-09-07）

対象版は `2026-09-07-history-recovery-2`。完了履歴の保存に失敗したまま次のクイズへ進める経路と、後から保存が成功しても失敗表示が残る経路を修正する。保存方式やシート構造を維持し、前回導入した履歴の再試行フラグがある完了結果だけを対象とする。

## 修正内容

- **A1：未保存履歴を残して次へ進む経路**。既存のクラウド送信待ちの保存確認後に、保留中の端末履歴を再試行する。失敗が続く場合は結果画面を保持する。名前なし・静的PWAも対象で、保存が回復したら「新しいクイズ」を再度押すことで進める。
- **A2：後続保存の成功後に失敗表示が残る経路**。現在の完了結果と名前・保存ID・得点などが一致する履歴を保存でき、その行が容量整理後も残る場合にだけ、再試行フラグを解除する。
- **A5：分類不明の表示**。品詞・テーマ・小テーマの内部値 `unknown` は、既存の「未分類」訳で表示する。難易度の `unknown` は従来どおり「レベル不明」とし、その他のラベルや分類キーは維持する。

履歴復旧後のセッション更新では容量整理を無効にする。その小さな書込みが失敗した場合は、メモリ上の履歴用フラグも再試行待ちに戻す。クラウドの保存確認状態や保存IDは戻さない。これにより、送信待ちの保存失敗とセッション書込み失敗が続くときにも、次の操作で復旧対象がなくなることを防ぐ。同じ処理を既存の履歴再試行経路でも使う。

明示的に消去した履歴のフラグはfalse、旧版のフラグは未指定のまま扱い、この修正を理由に再作成しない。保存できるのが空の履歴だけだった場合は成功とみなさない。

## 変更範囲と残る制約

変更は画面側の保存回復と表示、配信用の版番号、テスト、説明に限定する。得点計算、教材CSV・問題JSON、RHVoice / eo / spomenkaの既存音声、スクロールCSS、アカウントや公開設定の仕様、Google Sheetsの保存処理は変更しない。

保存領域が回復しない間は、履歴を保存できない完了結果から次のクイズへ進めない。エラー表示がある場合は結果画面を保持して保存状態を確認する。完了セッション自体も永続保存できない場合があるため、一律に再読込を勧めない。

既知のF1/F2（複数タブ）は未修正。学習開始前から同じブラウザでは1つのタブ・ウィンドウで利用する。一般の古い履歴の容量整理や履歴件数上限も変更しない。

監査A3（稼働中のシート列移動）・A4（重複した保存ID見出し）は今回見送る。管理者による列編集が条件であり、書込み前の通信追加や不正シートの扱いを含むため、今回の画面修正に混ぜない。正常な見出しを保ち、稼働中に列構造を変更しない運用を維持する。本番シートにこれらの問題が存在することを確認したという意味ではない。

## 検証方針

実際のアプリ関数を使い、変更前に失敗し変更後に成功することを確認する。履歴保存失敗、空履歴だけ保存可能、フラグ保存失敗、送信待ちの保存失敗、保存確認の記録失敗、同名の別結果、他の名前の結果、明示消去、連続した置換操作を含める。

ブラウザではローカル専用のメモリ内シートを使用する。新しいクイズを繰り返し押しても未保存結果を保持すること、後から履歴が保存されれば再読込なしで失敗表示が解除されることを確認する。既存のPC・スマートフォンでのスクロール、折りたたみ、公開設定、音声、多言語、保存確認の復元も回帰試験の対象とする。本番への障害注入やテスト得点の保存は行わない。

検証結果：Python 138件、JavaScript 98件、Chromium 30件すべて成功。アセット検査も成功し、WAV 15,768ファイルを確認した。別担当が保存回復の順序・連続操作と表示変更を独立確認した。
